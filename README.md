# 🐳 Контейнеризированный VPN-шлюз Fortinet (OpenConnect + Socat Proxy)

Документация по использованию и логике работы изолированного контейнера для подключения к корпоративной сети банка через протокол `fortinet` SSL-VPN / DTLS. 

Контейнер полностью замыкает сетевые маршруты внутри себя. Домашний интернет на хост-системе Windows 11 **не блокируется и не падает по скорости**, так как Windows вообще не знает про существование VPN-интерфейса.

---

## 🛠️ Спецификация системного окружения и библиотек

Сборка протестирована и стабильно функционирует на следующих версиях системных компонентов:

### 1. Хост-система (Windows 11)
* **Выпуск:** Windows 11 Pro
* **Версия:** 26H2
* **Сборка ОС:** 26300.9457
* **Функциональность:** Пакет интерфейса компонентов Windows 1000.26100.360.0
* **Docker Desktop:** Версия `4.94.0 (241994)`
* **Docker Engine (Server):** Версия `29.8.2` (API: `1.56`, Go: `go1.26.8`)

### 2. Подсистема виртуализации (WSL2)
* **Версия WSL:** `3.0.1.0`
* **Версия WSLg:** `1.0.79`
* **Версия ядра Linux (Kernel):** `6.18.40.1-1`

### 3. Окружение контейнера (Alpine Linux 3.21)
* **Базовый образ:** `alpine:3.21` (сборка на базе облегченной библиотеки `musl libc`)
* **OpenConnect:** Версия `v9.12` с поддержкой встроенного криптографического движка **OpenSSL 3.3.7** (7 Apr 2026).
* **Socat:** Версия `1.8.x` (утилита многопоточного реле трафика).

## Сборка образа

```bash
docker build --no-cache --rm -f "Dockerfile" -t connect:latest "."
```
---

## 🚀 Команда запуска собранного образа

Запуск контейнера выполняется строго во внешнем окне **PowerShell от имени Администратора** (это необходимо для корректного проброса TTY-терминала и бесконфликтного биндинга портов на хосте).

```bash
docker run --rm -it --privileged --cap-add=NET_ADMIN -e PORT_FORWARD="1111:{REMOTE_IP_ADDRESS}:{PORT}" -e VPN_HOST="{HOST}/{REALM}" -p "1111:1111" connect:latest --user={LOGIN}
```

### Разбор флагов запуска:
* `--privileged` и `--cap-add=NET_ADMIN` — дают контейнеру монопольные права на управление сетевым стеком внутри WSL2 и создание виртуального интерфейса `tun0`.
* `-e PORT_FORWARD="1111:{REMOTE_IP_ADDRESS}:{PORT}"` — переменная окружения, которую парсит внутренний скрипт. Направляет локальный порт контейнера `1111` на RDP-порт целевой рабочей машины `{PORT}`.
* `-p "1111:1111"` — пробрасывает порт `1111` из изолированного контейнера обратно на вашу физическую Windows 11.

## Подключение к удаленному рабочему столу (RDP)
1. Откройте стандартное Windows-приложение **«Подключение к удаленному рабочему столу»** (`mstsc`).
2. В поле **«Компьютер»** укажите локальный адрес моста: `127.0.0.1:1111`.
3. Нажмите кнопку *«Показать параметры»* (в левом нижнем углу).
4. **Важный нюанс авторизации (Домен):** В поле **«Пользователь»** обязательно вводите логин вместе с префиксом корпоративного домена банка в формате: `{domen}\{LOGIN}`. 
   * *Примечание:* Для самого Docker-контейнера на этапе VPN-подключения передается чистый логин `{LOGIN}`, но для RDP-сессии Windows домен `{domen}\` критически необходим.
5. Нажмите **Подключиться**.
